# กฎของทีม — Migration Workspace (ใช้กับทุกงานใน workspace นี้)

> ไฟล์นี้อยู่ที่ `kit/CLAUDE.kit.md` ของ workspace และถูก import จาก CLAUDE.md ของทุกงาน · แก้ผ่าน PR ของ kit เท่านั้น
> ถ้าขัดกับกฎส่วนกลางของ kit: กฎในไฟล์นี้ชนะเฉพาะเรื่องทีม / GitHub / สถานะ · OPEN_DECISIONS / GATES ของงานชนะทุกอย่าง

## กติกาสำคัญ 5 ข้อ

1. **1 งาน = 1 โฟลเดอร์ = 1 แชท = 1 branch** (`job/<PROJECT>/<job>/R<nn>`) · 1 PR = 1 งาน · ห้ามแก้ไฟล์ของงานอื่นจากแชทนี้
2. **จบขั้นต้อง `/update-status` แล้ว push** — กล่องสถานะต้องขึ้นบนจอทุกครั้ง
3. **ห้าม import โดยไม่ผ่าน `import-lock`** (ใบงานปักหมุด "ODI_DEV กำลังใช้งาน") และ `import-unlock` เมื่อเสร็จ
4. **✅ มาจากผู้อนุมัติเท่านั้น** — ทาง PR (`/approve Q14 B`) หรือผู้อนุมัติตอบในแชทแล้ว commit จากบัญชีตัวเอง · รูปแบบบรรทัด `✅ SA <YYYY-MM-DD> @<github-login>` · AI / เจ้าของงานติ๊กแทน = CI ไม่ผ่าน
5. **AI จะเขียนขึ้น GitHub หรือต่อฐาน ต้องได้รับอนุญาตก่อน** (รายละเอียดด้านล่าง)

## สถานะบนจอ (ไม่ต้องเปิดไฟล์เอง)

- จบขั้นไหนก็ตาม: รัน `python scripts/ws/job_status.py --box` แล้วแสดงกล่องสถานะ **ท้ายข้อความทุกครั้ง** ตามที่สคริปต์พิมพ์ — ห้ามแต่งตัวเลขเอง
- `/status` = ทุกขั้นของงานนี้ (16 ขั้น ✓ ▶ ⏳ ○ ⛔) · `/status list` = งานของฉันพร้อมเลขให้เลือก · `/status all` = ทั้งทีม
- ขั้นที่คนทำนอกแชท (รัน DDL · Smart Import · go-live) นับว่าเสร็จเมื่อมีหลักฐานเท่านั้น: DDL → แถว `DDL` ใน `status/DEPLOY_LOG.md` พร้อมผล SELECT ที่ยืนยัน · import → `status/IMPORT_LOG.md` (เขียนโดย import-unlock)
- ⛔ "สถานะไม่ตรง" = ไฟล์ขัดกัน → บอกผู้ใช้ว่าไฟล์ไหนขัด เสนอวิธีแก้พร้อม [แนะนำ] ไม่เดาแทน

## AI กับ GitHub (กลไก ⑤)

โหมดของงาน = `job.json` `github_mode` ถ้าตั้ง ไม่งั้นใช้ `shared/team.json` `github.mode` ของ workspace

| โหมด | อ่าน (fetch · pull · ดูใบงาน · ดูสถานะ branch ของคนอื่น) | เขียน (push · เปิดใบงาน · ใส่/เอาชื่อล็อก · comment) |
|---|---|---|
| 1 อ่านเอง-เขียนถาม | ทำได้เลย | **ถามทุกครั้ง** |
| 2 ถามทุกครั้ง | ถามทุกครั้ง | ถามทุกครั้ง |
| 3 คนทำเอง | ไม่ทำ — บอกคำสั่งให้คนรัน | ไม่ทำ — บอกคำสั่งให้คนรัน |

- การถาม: แสดงสิ่งที่จะทำแบบตรงตัวและที่ไหน เช่น "จะ push branch `job/SS_ESIM/…/R01` ขึ้น `origin` (3 commit: R01 build) · ให้ทำเลยไหม ตอบ ใช่ / ไม่ (ไม่ = ผมบอกคำสั่งให้คุณรันเอง)" แล้วรอ
- ได้ "ใช่" แล้วทำ → บันทึกใน `status/MIGRATION_STATUS.md`: "<วันเวลา> <สิ่งที่ทำ> · อนุญาตโดย <ชื่อ>"
- **ห้ามเสมอ ไม่มีโหมดไหนปลดได้:** push เข้า main · force-push · ลบ branch / ใบงาน · แก้ settings ของ repo · แก้เลขใบงาน — ถูกบล็อกด้วย hook `guard_github.py` · ห้ามหาทางอ้อม
- ห้ามใส่ `--yes` ให้ `workspace.py` แทนคน · ห้ามใช้ token / รหัสของใคร
- บังคับ 3 ชั้น: permission ของ Claude Code (ถามบนจอ) → hook `guard_github.py` → branch protection + token จำกัดสิทธิ์บน GitHub

## AI กับฐานข้อมูล

- โหมดของงาน (`job.json` `db_mode` > ค่าทีม): `auto` AI รัน `run_pack.py` ต่อเนื่อง · `ask` ถามก่อนรันทุกครั้ง · `human` คนรันทั้งหมด
- `run_pack.py` รับเฉพาะ SELECT / WITH คำสั่งเดียว · session READ ONLY · รหัสผ่านจากตัวแปร `ORA_RO_PASSWORD` บนเครื่องเท่านั้น
- **ห้ามรัน DDL / DML ทุก environment** · ห้ามขอ / รับ / พิมพ์รหัสผ่านในแชท · 0 แถวไม่นับว่าผ่าน · error ที่ไม่รู้จัก → `/diagnose` ไม่เดา
- โหมด human: ขอให้คนรันทีละ 1 อย่าง ตามลำดับ (1) เปิดไฟล์ไหน อยู่ที่ไหน (2) รันเพื่ออะไร (ภาษาง่าย) (3) export เป็นรูปแบบไหน (4) วางไฟล์ที่ไหน — หรือแนะนำคำสั่งเดียว `python scripts/runpack/run_pack.py <pack>` ให้คนรันเอง

## ของกลางและเลขของงาน

- ของกลาง (Smart Export · คอลัมน์ทั้ง schema) อยู่ที่ `shared/target/` ของ workspace · ในงานเป็นสำเนา `_shared_*` (ไม่ขึ้น Git) · ห้ามแก้ — ของกลางเปลี่ยนผ่าน `workspace.py update-target` เท่านั้น
- `odi.project_code` / `odi.id_base` มาจากเลขใบงาน (90000 + เลข × 1000) — **ห้ามแก้เอง** · เลขที่ยังไม่ยืนยัน (แบบคำนวณในเครื่อง) import ไม่ได้
- หลัง G3 รุ่นของกลางถูกล็อก — ของกลางเปลี่ยน = เปิดรอบใหม่ (`workspace.py new-round --kind target`)
